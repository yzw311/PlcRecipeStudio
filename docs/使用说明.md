# PlcRecipeStudio 使用说明

> PLC 多品牌配方管理软件（WPF 单机版 + 可选 API 宿主）。
> 当前版本：配方存取以 **Pfdoc 文件库（txt）为唯一事实源**；设备/用户/操作日志存 SQLite；MySQL 为 MES 阶段预留引擎。

---

## 1. 快速开始

1. 双击运行 `PlcRecipeStudio.exe`（首次运行自动建库、建配方文件夹）。
2. 首次安装必须先设置环境变量 `PLCRECIPE_INITIAL_ADMIN_PASSWORD`（至少 12 个字符）；账号为 `admin`，首次登录强制修改密码。
3. 主界面三栏：设备 → 配方 → 数据行。

数据目录：`%LOCALAPPDATA%\PlcRecipeStudio\`
```
├── Pfdoc\                     配方文件库（txt 即数据库，可直接备份/拷贝/手工编辑）
│   ├── 标准配方.txt            配方主文件（当前版本）
│   └── history\标准配方\       版本历史 v1.txt / v2.txt ...
├── backup\                    SQLite 自动备份（每日+启动后1分钟，保留份数可设置）
├── logs\                      Serilog 日志（保留30天）
├── plc-recipe.db              本地库（设备/用户/操作日志）
└── settings.json              软件设置
```

## 2. 配方文件库（Pfdoc）

- **txt 名 = 配方名**。软件里新建/复制/重命名/删除配方，文件同步增删改。
- **可直接用记事本编辑**，软件读取的就是编辑后的内容。数据行格式（9 字段竖线分隔，尾部可省略）：

```
名称|地址|类型|StringWords|值|下限|上限|单位|备注
温度|D100|Float32|8|12.5|10|80|℃|模温
```

- 类型取值：`Bool / Int16 / UInt16 / Int32 / UInt32 / Float32 / String`。
- 注意：**不要改动竖线数量结构**；`#` 开头的行为注释；`Key=值` 行为元数据（Name/Version/Device 等）。
- 变量名/单位/备注/字符串值**不能包含竖线 `|` 或换行符**（保存时会拦截；PLC 读回的字符串若含 `|`，落库时自动替换为全角 `｜`）。
- 配方名避免 `/ \ : * ? " < > |` 字符（文件名限制，自动替换为 `_`）。
- 同名 txt 全局唯一：两台设备不能有同名配方（软件保存时会提示“已存在”）。

## 3. 版本历史与回滚

- 每次保存/上传落库自动在 `Pfdoc\history\配方名\` 下留快照 `v{N}.txt`（含操作人/时间/变更说明）。
- 工作台 → 配方右键 → **历史版本**：查看任意版本与当前版本的逐行差异（黄=修改、蓝=新增、红=当前独有），点“回滚此版本”→ 回滚保存为新版本，任何版本都不会丢失。

## 4. 下载 / 上传（PLC 交互）

### 手动
- 工作台勾选“批量目标”（同品牌其他设备）→ **下载**：把配方值写入 PLC（可选下载前对比、下载后回读校验，见设置）。
- **上传**：读 PLC 当前值 → 按变量名落库。

### 信号联动（PLC 主动发起，需在设备编辑里配置并启用）
| PLC 侧动作 | 软件行为 |
|---|---|
| 把配方名写入“配方名地址”，置位“下载请求位” | 到 `Pfdoc` 找同名 txt → **找到则下载内容并置完成位；找不到置失败位** |
| 把配方名写入“配方名地址”，置位“上传请求位” | 按 Pfdoc 同名 txt 的结构读 PLC 值 → 更新该 txt（版本+1）；**txt 不存在则自动新建** |

- 握手闭环：PLC 清请求位后，软件自动复位完成/失败位。
- 轮询连续失败 3 次进入 30 秒周期探测，设备恢复后自动继续。
- **配方标识（水印）**：配置“配方标识地址”后，每次下载成功自动写入 `配方名|v版本` 并回读核对——产线/MES 可随时读取该区核对设备在用配方。

## 5. 账号与安全

- 角色：操作员 < 工程师 < 管理员。设备增删改、配方下载需工程师及以上；用户管理仅管理员。
- 连续 5 次登录失败锁定 10 分钟。
- 内置 admin / 新建账号首次登录强制改密。
- 登录页默认**不显示**默认口令提示（系统管理 → 软件设置可开启；产线部署建议保持关闭）。
- 密码哈希为 PBKDF2-SHA256（60 万次迭代 + 随机盐）；旧版本账号在下次成功登录时自动升级到新强度。
- 登录成功/失败、配方上传下载、参数越界均记入操作日志（系统管理 → 操作日志）。

## 6. 数据库与 MES

- 默认 **SQLite**（本地单机，零配置），每日自动备份到 `backup\`，保留份数可设置。
- 切换 **MySQL**（多工作站/MES）：系统管理 → 软件设置 → 数据库引擎选 MySQL、填连接串 → **重启生效**。
  - 连接串示例：`Server=localhost;Database=plc_recipe;Uid=root;Pwd=xxx`
  - 首次启动自动建库建表；**Pfdoc txt 不受影响**（配方始终在文件库）。
  - SQLite 里的设备/用户/日志不自动搬迁（需要时联系开发提供迁移）。

## 7. API 宿主（PlcRecipe.Server，MES 集成入口）

```
dotnet run --project PlcRecipe.Server        # 默认 http://localhost:5000
```
- `GET /health`、`GET /api/health`（数据库+设备状态）
- 设备/配方 CRUD、版本历史、回滚、上传/下载、操作日志（端点清单见 Program.cs 头注释）
- `/hubs/plc` SignalR 实时推送设备状态（连接串携带 `?key=<ApiKey>`）
- 鉴权（安全默认）：settings.json 的 `ApiKey` **为空时 /api/* 一律 503 拒绝**（API 关闭）；配置后 `/api/*` 需带 `X-Api-Key` 头、SignalR 需带 `?key=`。ApiKey 可在 WPF 系统管理 → 软件设置里填写（或手工编辑 settings.json 后重启服务端）
- ⚠️ SQLite 模式下请勿与本机 WPF 同时运行；多工作站请切 MySQL

## 8. 故障排查

| 现象 | 排查 |
|---|---|
| 启动报“MySQL 连接串未配置” | settings.json 填 `DatabaseConnectionString`，或引擎切回 SQLite |
| API 请求全部 503 | settings.json 的 `ApiKey` 为空（安全默认 API 关闭），配置后重启服务端 |
| SignalR 连接被拒 | 连接串加 `?key=<ApiKey>`（与 settings.json 一致） |
| 设备列表配方不见了 | 检查 txt 头部 `Device=` 是否为当前设备名（设备改名会自动同步；手工改名的设备需手工改 txt） |
| 下载报“配方库中不存在配方” | Pfdoc 里没有同名 txt：手工补一个，或先在软件里保存该名字的配方 |
| 下载报“字符串超出上限” | 加大设备编辑里的“配方标识字数”或数据行 StringWords |
| settings.json 疑似被重置 | 查看数据目录下 `settings.json.corrupt-*` 备份与 `logs\` 里的 Warning（文件损坏会回退默认值并留备份） |
| 操作日志时间 | 库内统一 UTC，界面显示本地时间 |
| 一切异常 | 看 `logs\app-日期.log` |
